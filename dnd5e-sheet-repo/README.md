# D&D 5e — Лист персонажа

Веб-приложение: интерактивный лист персонажа D&D 5e (редакции 2014/2024) с
аккаунтами, облачным хранением через Cloudflare D1, мастером создания
персонажа и ручным заполняемым листом. Без сборщиков и npm-зависимостей —
чистый HTML/CSS/JS на фронтенде и один файл на Cloudflare Worker.

## Структура

```
frontend/           — статический сайт (деплоится на Cloudflare Pages)
  index.html
  css/style.css
  js/
    config.js        — сюда вписать адрес Worker'а после деплоя
    api.js            — клиент API (fetch + токен в localStorage)
    dice.js            — бросок кубиков
    diceModal.js       — модалки бросков
    character.js        — вычисляемые поля листа (модификаторы, КД, ...)
    router.js            — простой hash-роутер
    dom.js                 — вспомогательные функции рендера
    data/dnd5e-data.js      — расы/классы/предыстории/заклинания (SRD, расширяемо)
    views/
      auth.js               — вход/регистрация
      list.js                — список персонажей
      sheet.js                — сам лист персонажа
      wizard.js                — пошаговый мастер создания

worker/worker.js    — Cloudflare Worker (API), вставляется в дашборд целиком
src-schema/schema.sql — SQL-схема для D1, выполнить один раз в консоли D1

serve.js             — локальный сервер для разработки (node serve.js)
worker/test-worker.mjs — smoke-тесты Worker'а на моках (node worker/test-worker.mjs)
```

## Деплой (без установки чего-либо — всё через панель Cloudflare)

### 1. Создать базу данных D1
1. Откройте dash.cloudflare.com → **Workers & Pages → D1**.
2. «Create database», назовите, например, `dnd5e-sheet-db`.
3. Откройте вкладку **Console** этой базы и вставьте содержимое
   `src-schema/schema.sql`, выполните.

### 2. Создать и вставить Worker
1. **Workers & Pages → Create → Create Worker**, назовите, например,
   `dnd5e-sheet-api`, разверните с шаблоном "Hello World".
2. Откройте **Edit code** и полностью замените содержимое на
   `worker/worker.js`. Сохраните и разверните (Deploy).
3. **Settings → Variables**:
   - Bindings → **D1 Database binding**: имя `DB`, база — та, что создали на шаге 1.
   - Variables → добавьте `ALLOWED_ORIGIN` = адрес вашего будущего Pages-сайта
     (можно временно поставить `*`, потом сузить).
4. Скопируйте адрес воркера вида
   `https://dnd5e-sheet-api.<ваш-поддомен>.workers.dev`.

### 3. Прописать адрес API во фронтенде
Откройте `frontend/js/config.js` и замените `API_BASE_URL` на адрес из шага 2.4.

### 4. Задеплоить фронтенд на Cloudflare Pages
1. **Workers & Pages → Create → Pages → Direct Upload**.
2. Перетащите папку `frontend` целиком (или файлы из неё).
3. После деплоя скопируйте адрес Pages-сайта и вернитесь в настройки Worker'а
   (шаг 2.3), обновите `ALLOWED_ORIGIN` на этот адрес.

Готово — открывайте Pages-адрес, регистрируйтесь и создавайте персонажей.

## Локальная разработка (в этой песочнице/на своей машине)

```
node serve.js                # статика фронтенда на http://localhost:8080
node worker/test-worker.mjs  # smoke-тесты API-логики на моках D1
```

Реальный Worker локально не поднимается без Wrangler (он не ставится в этой
песочнице из-за отсутствия доступа к npm) — но `test-worker.mjs` проверяет
всю логику авторизации и CRUD персонажей на in-memory моке D1, так что
сама логика Worker'а проверена ещё до деплоя.

## Что уже есть

- Аккаунты (email/пароль), сессии, персонажи привязаны к пользователю
- Пошаговый мастер: редакция → раса → класс → предыстория → характеристики
  (стандартный массив / покупка очков / вручную) → навыки → заклинания (если есть) → итог
- Полный ручной лист: характеристики/модификаторы, спасброски, 18 навыков
  (владение/экспертиза), КД/ХП/кости хитов/спасброски от смерти, атаки,
  заклинания (ячейки, известные/подготовленные), инвентарь, деньги, черты,
  владения и языки, личность/предыстория, спутники
- Клик по любому модификатору/навыку/спасброску — бросок к20 (обычный/преим./помеха)
- Свободный бросок кубиков (к4–к20, к100, произвольное выражение) + журнал бросков
- Автосохранение в облако (с индикатором) — ручное обновление, без live-совместной работы

## Что дальше (не реализовано в этой версии)
